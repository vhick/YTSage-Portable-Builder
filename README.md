# YTSage True Portable — Community Build Kit

**Status:** build scripts prepared and Python patch tested; **Windows build and actual AppData/registry portability have not been verified**.

**Target:** official upstream [oop7/YTSage](https://github.com/oop7/YTSage), default version `v5.6.0` (released October 14, 2026).

## What this package contains

- `.github/workflows/build-ytsage-true-portable.yml` — manual-only Windows GitHub Action.
- `portable-kit/patch_upstream.py` — applies two Windows source patches to a fresh checkout of the specified YTSage release, failing closed if upstream code changes.
- `portable-kit/YTSagePortable.cs` — independent community Windows launcher, compiled by GitHub Actions.
- `portable-kit/package.ps1` — packages the frozen GUI and bundled, SHA-256-checked FFmpeg into a true portable layout.
- `portable-kit/appinfo.ini`, `YTSagePortable.ini` — PortableApps.com-format metadata and optional reference recipe for the official PAL generator.
- `portable-kit/build-paf-locally.ps1` — optional helper for a separately installed official PortableApps.com Installer.
- `portable-kit/verify_package.py` — checks basic ZIP contents before upload.

**No app executable is in this kit.** The workflow downloads official YTSage source, builds it and emits a ZIP artifact. The user must run that workflow in their own GitHub repository. The package ZIP generated by Actions is different from this setup kit.

## Install build kit into a fork (beginner path)

1. On GitHub, **Fork** `https://github.com/oop7/YTSage` to your own account. If you already have that fork, use it.
2. Download this **build kit ZIP**, then extract it locally.
3. In your fork, add **both** `.github/workflows/build-ytsage-true-portable.yml` and the entire `portable-kit` folder from the ZIP. **Preserve their directory names and structure.** A GitHub Desktop clone makes uploading directories easiest.
4. Commit the added files to your fork's default branch. Leave the official upstream Windows release workflow alone.
5. Open your fork on GitHub → **Actions** → **Build YTSage True Portable (Manual)** → **Run workflow**.
6. Leave **upstream_ref** as `v5.6.0` for the currently verified source layout. On a future stable version, enter its official tag, such as `v5.7.0` (only if that version exists).
7. After the successful run, open that Actions run. Under **Artifacts**, download `YTSage-TruePortable-5.6.0` (or the version selected), then extract the artifact ZIP. Inside is `YTSage-v5.6.0-TRUE-Portable.zip`.
8. Extract that ZIP into a folder and **launch only `YTSagePortable.exe`** (not the inner `App\YTSage\YTSage.exe`, which bypasses the portable launcher).

The workflow runs on `windows-latest` using `cx_Freeze` and downloads **pinned FFmpeg 9.0.2 essentials** with the exact SHA-256 digest from the upstream Windows build workflow. It does **not** automatically publish a release, push code, or create an installer. The ZIP artifact is retained for **7 days**; change `retention-days: 7` under the upload step if desired.

## Expected packaged layout

```text
YTSagePortable/
  YTSagePortable.exe         <-- always launch this
  App/
    YTSage/
      YTSage.exe
      ffmpeg.exe
      ffprobe.exe
      lib/ ...
    AppInfo/
      appinfo.ini
      appicon.ico
      appicon_16.png
      appicon_32.png
      appicon_128.png
      Launcher/YTSagePortable.ini
  Data/
    README.txt
    YTSage/                 <-- generated on first run
      data/ytsage_config.json
      data/ytsage_history.json
      bin/                 <-- yt-dlp.exe, deno.exe managed here
      logs/
    DenoCache/
    Cache/
    yt-dlp-config/
    Temp/
  Other/Source/
    LICENSE.txt
    buildinfo.txt
```

In portable mode the application’s YTSage data-root is overridden, while leaving normal installations unchanged. The launcher also sets Deno cache, XDG cache/config and the child-process `TEMP`/`TMP` to subfolders of the portable directory. It **does not** override global system `LOCALAPPDATA`, `APPDATA`, `USERPROFILE`, or global `PATH` because that could break extracting existing browser cookies and other features. It sets a **child-process-only** PATH to find the bundled FFmpeg.

The source patch disables YTSage's Windows FFmpeg installer when portable mode is active because the upstream installer can call `setx PATH` (a permanent user-setting change). Use the FFmpeg included in this package.

### Important limitations

- This is **not** an officially approved PortableApps.com release. It uses custom community launcher executable rather than the official PortableApps.com Launcher. A suitable `AppInfo` and PAL recipe are included for a future official launcher build.
- The action currently creates the **portable ZIP**; it does **not** automatically build a `.paf.exe`. To create a `.paf.exe` you must obtain the official [PortableApps.com Installer](https://portableapps.com/apps/development/portableapps.com_installer) and compile the extracted ZIP's `YTSagePortable` directory. A helper script is supplied. Do not just rename `.zip` to `.paf.exe`.
- Settings and download history can contain **absolute output file paths**. If moving to another USB drive letter, change the download destination inside YTSage. Existing history file links may still point to the original drive.
- The launcher cannot prevent **Windows-managed** traces (such as Prefetch) or every file side effect of a browser or Windows library. Do not claim 'zero host traces' without ProcMon and before/after registry tests.
- Choosing `Extract cookies from browser` reads the existing browser’s profile. It intentionally does not move, rewrite or clean other browsers’ profile directories.
- Portable mode redirects YTSage's explicit file locations, but upstream changes and other dependencies may introduce new locations. Test new releases before distributing.
- **Never launch the inner EXE directly**: no environment redirection occurs, so it would write to default `%LOCALAPPDATA%\YTSage`.

## Create a `.paf.exe` manually (optional)

After building your portable ZIP in Actions, use the official [PortableApps.com Installer](https://portableapps.com/apps/development/portableapps.com_installer) on Windows:

1. Extract the built ZIP. You should see `YTSagePortable\App`, `YTSagePortable\Data`, and `YTSagePortable.exe`.
2. Install/run **PortableApps.com Installer** (separate development tool).
3. Give the installer the `YTSagePortable` directory. Or run `portable-kit/build-paf-locally.ps1` with `-PortableZip` and `-PortableAppsInstallerExe`.
4. Validate the resulting `.paf.exe` and its root launcher. The included custom launcher is intended for Windows 10/11 and requires .NET Framework 4.x.

**Note:** The official tool might require app-format adjustments and icon checks; the `.paf.exe` generation is not CI-validated.

## Portability test plan (do this before calling it truly portable)

1. On Windows, note whether these exist before launching: `%LOCALAPPDATA%\YTSage`, `%APPDATA%\YTSage`, `%LOCALAPPDATA%\ffmpeg`. Preserve any pre-existing files.
2. Run `YTSagePortable.exe`, change a setting, and download a test video you are allowed to download.
3. Check the new settings file under `Data\YTSage\data\ytsage_config.json`, yt-dlp / Deno binaries under `Data\YTSage\bin` and log files under `Data\YTSage\logs`.
4. Close and reopen. Confirm preferences/history persist. Try updating yt-dlp and downloading Deno from inside the app.
5. Verify the Windows **user/system PATH values** were not modified; compare pre/post AppData and registry with ProcMon or Regshot.
6. Move the entire folder to another drive letter. Start again and verify settings; adjust the downloads destination if needed.
7. Test cookies-from-browser separately with a non-sensitive profile. Confirm other browser profiles are not modified.

If the source changes or any patch fails, **do not remove the fail-closed safety check**. Update the patch after reading the new upstream implementation.
